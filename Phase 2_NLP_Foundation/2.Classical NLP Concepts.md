## 1. Bag of Words (BoW)

### Definition
Bag of Words is a text representation technique that converts text into numerical features by counting how many times each word appears in a document.

It is called a "bag" because it generally ignores word order and focuses on word occurrence or frequency.

### Example

Consider these three documents:

- Document 1: "I love AI"
- Document 2: "I love NLP"
- Document 3: "AI is useful"

### Step 1: Create a Vocabulary

Collect all unique words from the documents.

Vocabulary:
["I", "love", "AI", "NLP", "is", "useful"]

Vocabulary size = 6

### Step 2: Count Word Occurrences

Represent each document using the vocabulary.

| Document | I | love | AI | NLP | is | useful |
|---|---:|---:|---:|---:|---:|---:|
| Document 1 | 1 | 1 | 1 | 0 | 0 | 0 |
| Document 2 | 1 | 1 | 0 | 1 | 0 | 0 |
| Document 3 | 0 | 0 | 1 | 0 | 1 | 1 |

Each row represents a document, and each column represents a vocabulary word.

For example, Document 1 becomes:

[1, 1, 1, 0, 0, 0]

The value 1 means the word occurs once, while 0 means it does not occur.

If a word occurs three times, its count would be 3.

### Python Example

```python
from sklearn.feature_extraction.text import CountVectorizer

documents = [
    "I love AI",
    "I love NLP",
    "AI is useful"
]

vectorizer = CountVectorizer()
bowMatrix = vectorizer.fit_transform(documents)

print("Vocabulary:", vectorizer.get_feature_names_out())
print("BoW Matrix:")
print(bowMatrix.toarray())
```

Note: CountVectorizer lowercases text by default and normally removes single-character tokens using its default token pattern. Therefore, the actual output may omit "I".

### Advantages
- Simple and easy to understand.
- Converts text into numerical data.
- Works well with traditional machine-learning algorithms.
- Useful for basic document classification.

### Limitations
- Ignores word order.
- Does not understand word meaning.
- Can produce large, sparse feature matrices.
- May treat words with similar meanings as completely different.

## 2. TF-IDF (Term Frequency–Inverse Document Frequency)

### Definition
TF-IDF is a numerical technique that measures how important a word is in a particular document compared with a collection of documents.

It gives higher importance to words that appear frequently in a document but are relatively uncommon across the document collection.

For example, the word "the" may appear in many documents, so it usually provides little information for distinguishing one document from another.

### Components of TF-IDF

#### A. Term Frequency (TF)

Term Frequency measures how often a term occurs in a document.

A simple formula is:

TF(t, d) = Number of occurrences of term t in document d

Example:

Document:
"AI is useful. AI is powerful."

The word "AI" appears twice.

TF(AI, document) = 2

Some implementations normalize TF by document length.

#### B. Inverse Document Frequency (IDF)

Inverse Document Frequency measures how rare or informative a term is across a collection of documents.

A common formula is:

IDF(t) = log(N / df(t))

Where:
- N = Total number of documents.
- df(t) = Number of documents containing term t.
- log = Logarithm.

A term appearing in almost every document receives a lower IDF value.

A term appearing in only a few documents receives a higher IDF value.

Different implementations use different smoothing and normalization formulas.

#### C. TF-IDF Formula

TF-IDF(t, d) = TF(t, d) × IDF(t)

A word receives a higher score when it is frequent in a document but uncommon across the document collection.

### Example

Consider these documents:

- Document 1: "AI is powerful"
- Document 2: "AI is useful"
- Document 3: "AI improves healthcare"

The word "AI" appears in all three documents, so it has relatively low IDF.

The word "healthcare" appears in only one document, so it has a higher IDF.

Therefore, "healthcare" may receive a higher TF-IDF score in Document 3 than "AI", depending on the TF and IDF formulas used.

### Python Example

```python
from sklearn.feature_extraction.text import TfidfVectorizer

documents = [
    "AI is powerful",
    "AI is useful",
    "AI improves healthcare"
]

vectorizer = TfidfVectorizer()
tfidfMatrix = vectorizer.fit_transform(documents)

print("Features:", vectorizer.get_feature_names_out())
print("TF-IDF Matrix:")
print(tfidfMatrix.toarray())
```

### Applications
- Search engines.
- Document retrieval.
- Keyword extraction.
- Text classification.
- Finding important words in documents.

### Advantages
- Reduces the relative importance of very common words.
- Helps identify informative terms.
- Works well with traditional machine-learning models.

### Limitations
- Does not truly understand word meaning.
- Usually treats words as separate features.
- May fail to recognize synonyms.
- Does not inherently understand context.

## 3. N-grams

### Definition
An N-gram is a continuous sequence of N items from text. These items can be words or characters.

In word-based N-grams, N indicates how many consecutive words are included in each group.

### Types of N-grams

#### A. Unigrams (N = 1)

A unigram contains one word.

Sentence:
"I love machine learning"

Unigrams:
- I
- love
- machine
- learning

#### B. Bigrams (N = 2)

A bigram contains two consecutive words.

Bigrams:
- I love
- love machine
- machine learning

#### C. Trigrams (N = 3)

A trigram contains three consecutive words.

Trigrams:
- I love machine
- love machine learning

#### D. Four-grams (N = 4)

A four-gram contains four consecutive words.

Example:
"I love machine learning"

Four-gram:
- I love machine learning

### Example Table

Sentence: "Natural language processing is useful"

| N-gram Type | Examples |
|---|---|
| Unigrams | Natural, language, processing, is, useful |
| Bigrams | Natural language, language processing, processing is, is useful |
| Trigrams | Natural language processing, language processing is, processing is useful |
| Four-grams | Natural language processing is, language processing is useful |

### Formula

For a sequence containing L words, the number of consecutive word N-grams is:

Number of N-grams = L - N + 1

This formula applies when L is at least N.

Example:

Sentence: "I love learning NLP"

Number of words = 4

Number of bigrams = 4 - 2 + 1 = 3

The bigrams are:
- I love
- love learning
- learning NLP

### Python Example

```python
from sklearn.feature_extraction.text import CountVectorizer

documents = [
    "I love machine learning",
    "I love natural language processing"
]

vectorizer = CountVectorizer(ngram_range=(1, 2))
ngramMatrix = vectorizer.fit_transform(documents)

print("Features:", vectorizer.get_feature_names_out())
print("Matrix:")
print(ngramMatrix.toarray())
```

The range `(1, 2)` generates both unigrams and bigrams.

### Applications
- Search engines.
- Text prediction.
- Spam detection.
- Sentiment analysis.
- Detecting common phrases.
- Basic language modeling.

### Advantages
- Captures some local word order.
- Identifies common phrases.
- Can distinguish expressions such as "not good" from "good" when bigrams are included.

### Limitations
- The number of possible N-grams can grow rapidly.
- Rare N-grams may not appear in training data.
- Larger N-grams require more data.
- Captures local patterns but not the full meaning of a sentence.

## 4. Text Classification

### Definition
Text classification is an NLP task in which a computer assigns one or more predefined categories to a piece of text.

The input may be a sentence, email, review, news article, or document.

The output is a predicted category or label.

### Examples

#### A. Email Spam Detection

Input:
"Congratulations! You have won a free prize."

Predicted label:
SPAM

#### B. Sentiment Analysis

Input:
"The product is excellent."

Predicted label:
POSITIVE

Input:
"The product is terrible."

Predicted label:
NEGATIVE

#### C. News Classification

Input:
"Pakistan won the cricket match."

Predicted category:
SPORTS

Input:
"The stock market showed strong growth."

Predicted category:
BUSINESS or FINANCE

#### D. Support Ticket Classification

Input:
"I cannot reset my password."

Predicted category:
ACCOUNT SUPPORT

### How Text Classification Works

1. Collect labeled text examples.
2. Preprocess the text when appropriate.
3. Convert the text into numerical features using BoW, TF-IDF, or another representation.
4. Train a classification algorithm.
5. Evaluate the trained model.
6. Predict labels for new text.

### Example

| Text | Label |
|---|---|
| I love this product | Positive |
| This product is amazing | Positive |
| I hate this product | Negative |
| The service was terrible | Negative |

The model learns patterns associated with each category and uses them to classify new examples.

### Python Example

This example trains a simple sentiment classifier using TF-IDF and Logistic Regression.

```python
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import make_pipeline

texts = [
    "I love this product",
    "This product is amazing",
    "The experience is excellent",
    "I hate this product",
    "This product is terrible",
    "The experience is awful"
]

labels = [
    "positive",
    "positive",
    "positive",
    "negative",
    "negative",
    "negative"
]

model = make_pipeline(
    TfidfVectorizer(),
    LogisticRegression()
)

model.fit(texts, labels)

newText = ["This product is excellent"]
prediction = model.predict(newText)

print("Predicted sentiment:", prediction[0])
```

The prediction is expected to be positive, but actual performance depends on the training data and learned features.

### Common Classification Algorithms
- Naive Bayes.
- Logistic Regression.
- Support Vector Machines (SVM).
- Decision Trees.
- Random Forests.

### Advantages
- Automates the categorization of large amounts of text.
- Can be efficient for structured classification tasks.
- Often works well with BoW and TF-IDF features.

### Limitations
- Requires suitable labeled training data for supervised learning.
- May struggle with sarcasm, ambiguity, and context.
- Can learn biases present in the training data.
- Performance may decrease when real-world text differs from training examples.

## 5. Named Entity Recognition (NER) — Concept

### Definition
Named Entity Recognition (NER) is an NLP task that identifies important named entities in text and classifies them into categories.

Entities can include:
- People.
- Organizations.
- Locations.
- Dates.
- Times.
- Money amounts.
- Products or other domain-specific entities.

NER focuses on identifying and categorizing entities rather than simply classifying the entire document.

### Example

Sentence:

"Ali joined Microsoft in Lahore on 10 January 2026."

Possible NER output:

| Entity | Entity Type |
|---|---|
| Ali | PERSON |
| Microsoft | ORGANIZATION |
| Lahore | LOCATION |
| 10 January 2026 | DATE |

### How NER Works Conceptually

1. Receive a sentence or document.
2. Process the text into tokens.
3. Identify spans of text that refer to entities.
4. Assign a category to each identified entity.
5. Return the entities and their labels.

Example:

Text:
"Apple opened a new office in London."

Possible entities:
- Apple → ORGANIZATION
- London → LOCATION

The word "Apple" can also refer to a fruit. The correct interpretation depends on context.

### Applications
- Extracting names from documents.
- Analyzing news articles.
- Processing resumes and job applications.
- Extracting organizations and locations from business reports.
- Information retrieval.
- Medical and legal document analysis.

### NER vs. Text Classification

| Text Classification | Named Entity Recognition |
|---|---|
| Assigns categories to a text | Identifies and categorizes entities within text |
| Input: "I love this phone" | Input: "Ali bought an iPhone in Lahore" |
| Output: Positive sentiment | Output: Ali = PERSON, iPhone = PRODUCT, Lahore = LOCATION |
| Usually labels a whole text | Usually labels specific words or spans |

### Limitations
- The same name may refer to different entities.
- Some entities are difficult to distinguish without context.
- Domain-specific names may be unfamiliar.
- Entity boundaries and categories can be ambiguous.

## 6. Semantic Similarity

### Definition
Semantic similarity measures how closely two pieces of text are related in meaning.

Two sentences can use different words but express similar ideas.

### Example 1: Similar Meaning

Sentence A:
"I am happy."

Sentence B:
"I feel joyful."

These sentences use different words but have similar meanings.

Their semantic similarity should generally be high.

### Example 2: Different Meaning

Sentence A:
"I love programming."

Sentence B:
"The weather is cold."

These sentences discuss different subjects, so their semantic similarity would generally be lower.

### Lexical Similarity vs. Semantic Similarity

Lexical similarity measures how similar the actual words or character patterns are.

Semantic similarity focuses on meaning.

Example:

Sentence A:
"The car is fast."

Sentence B:
"The automobile is quick."

These sentences have relatively few identical words, but they express similar meanings.

A basic word-overlap method may consider them less similar, while a good semantic representation may identify their similarity.

### How Semantic Similarity Can Be Measured

#### A. Word Overlap
Compares the words shared by two texts.

Example:
- Text A: "I like AI"
- Text B: "I like NLP"

Shared words:
"I", "like"

This method is simple but does not understand meaning.

#### B. TF-IDF with Cosine Similarity
Represents each text as a numerical vector using TF-IDF, then measures the angle between the vectors.

Cosine similarity is commonly calculated as:

cosineSimilarity(A, B) = (A · B) / (||A|| × ||B||)

Where:
- A and B are numerical vectors.
- A · B is their dot product.
- ||A|| and ||B|| are their vector magnitudes.

A score closer to 1 indicates that the vectors point in a similar direction.

For nonnegative TF-IDF vectors, scores typically range from 0 to 1.

This approach measures similarity based on weighted word overlap, not a full understanding of meaning.

#### C. Word Embeddings and Sentence Embeddings
Modern NLP systems can represent words or entire sentences as dense numerical vectors.

These vectors can capture semantic relationships more effectively than simple word-count features.

For example:
- "I am happy."
- "I feel joyful."

A suitable sentence-embedding model may generate vectors with high cosine similarity.

### Python Example: TF-IDF Cosine Similarity

```python
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.metrics.pairwise import cosine_similarity

sentences = [
    "I love machine learning",
    "I enjoy machine learning",
    "The weather is cold"
]

vectorizer = TfidfVectorizer()
vectors = vectorizer.fit_transform(sentences)

similarityMatrix = cosine_similarity(vectors)

print(similarityMatrix)
print("Similarity between sentence 1 and 2:",
      similarityMatrix[0, 1])
```

The first two sentences share several words and are likely to receive a higher score than a comparison between the first and third sentences.

However, TF-IDF cosine similarity may underestimate semantic similarity when sentences use different words with similar meanings.

### Applications
- Search engines.
- Duplicate question detection.
- Document matching.
- Resume-to-job description matching.
- Recommendation systems.
- FAQ matching and information retrieval.

### Limitations
- Word overlap does not always reflect meaning.
- TF-IDF may miss synonyms and paraphrases.
- Similarity scores depend on the representation and method.
- Even embedding-based methods can struggle with negation, subtle context, and specialized terminology.

## 7. Limitations of Traditional NLP Approaches

Traditional NLP approaches commonly use manually designed features, word counts, statistical weighting, dictionaries, or relatively simple machine-learning models.

Examples include:
- Bag of Words.
- TF-IDF.
- N-grams.
- Naive Bayes.
- Logistic Regression.
- Traditional rule-based NER.

These approaches remain useful, but they have important limitations.

### A. Lack of Deep Context Understanding

Traditional word-based methods often represent text using individual words and their frequencies.

Example:

Sentence 1:
"The movie is good."

Sentence 2:
"The movie is not good."

A simple BoW representation records many of the same words in both sentences. It may fail to adequately capture the effect of "not".

Adding bigrams can help because "not good" becomes a separate feature, but this does not solve every contextual problem.

### B. Difficulty Understanding Word Meaning

Traditional methods often treat different words as unrelated features.

Example:
- Happy.
- Joyful.
- Delighted.

These words have similar meanings, but BoW does not inherently recognize that relationship.

Embedding-based methods can represent semantic relationships more effectively.

### C. Loss of Word Order

Bag of Words ignores word order.

Example:
- "Dog bites man."
- "Man bites dog."

Both sentences have the same word counts, so a basic BoW representation cannot distinguish their meanings.

N-grams preserve some local word order, but they do not fully represent long-range relationships.

### D. High Dimensionality

A vocabulary containing thousands of unique words may produce thousands of features for each document.

For example, if the vocabulary contains 20,000 terms, a BoW representation may contain 20,000 feature positions per document.

Most documents contain only a small fraction of these words, resulting in sparse feature vectors.

This can increase memory usage and computational costs.

### E. Data Sparsity

Some words and N-grams appear rarely in training data.

For example:
"AI improves agricultural productivity."

A model trained mostly on technology-related sentences may not have seen this exact combination of words.

Rare features may not provide enough evidence for reliable predictions.

### F. Limited Generalization

Traditional models may perform poorly when they encounter unfamiliar words, new slang, spelling variations, or a new domain.

Example:
A sentiment classifier trained on restaurant reviews may not work equally well on medical reviews.

The meaning and importance of terms can differ across domains.

### G. Difficulty with Ambiguity and Sarcasm

Example:
"Great! Another problem with my laptop."

The word "Great" is usually positive, but the sentence may express frustration or sarcasm.

A simple word-based sentiment classifier may incorrectly label it as positive.

### H. Feature Engineering Requirements

Traditional approaches often require decisions about:
- Which preprocessing steps to use.
- Which features to extract.
- Whether to use unigrams, bigrams, or trigrams.
- Which classification algorithm to select.
- How to handle rare words and class imbalance.

Poor feature choices can reduce model performance.

### I. Limited Long-Range Relationships

N-grams capture only a fixed number of consecutive tokens.

For example, an important relationship between the beginning and end of a long paragraph may be difficult to represent using small N-grams.

Modern contextual language models can often capture longer relationships more effectively, although they also have limitations.

### J. Dependence on Training Data

A traditional model learns patterns from its training examples.

If the training data contains biased, inaccurate, or unrepresentative examples, the model may produce biased or inaccurate predictions.

### Summary Table

| Limitation | Explanation |
|---|---|
| Weak context understanding | May miss meaning that depends on surrounding text |
| Limited semantic understanding | May treat synonyms as unrelated words |
| Loss of word order | BoW ignores word sequence |
| High dimensionality | Large vocabularies create many features |
| Data sparsity | Many possible features occur rarely |
| Poor generalization | May struggle with unfamiliar language or domains |
| Ambiguity and sarcasm | Literal words may not express intended meaning |
| Feature engineering | Often requires manual feature and preprocessing choices |
| Limited long-range modeling | Small N-grams capture only local patterns |
| Training-data dependence | Biased data can produce biased predictions |

### Traditional NLP vs. Modern NLP

| Traditional NLP | Modern NLP |
|---|---|
| Often uses BoW and TF-IDF | Often uses learned embeddings and contextual representations |
| Frequently relies on manually designed features | Can learn useful representations from data |
| Usually treats words independently in basic models | Can model context and relationships between tokens |
| Often computationally inexpensive for small tasks | Large neural models may require significant computation |
| Works well for many simple classification tasks | Often performs better on complex language tasks |
| Usually requires task-specific training | Some pretrained models can perform new tasks with limited examples |

Important: Modern NLP is not always better for every situation. Traditional methods can be faster, easier to interpret, cheaper to deploy, and highly effective for small or well-defined datasets.

## 8. Complete Practical Comparison

Suppose we have the following customer review:

"The product is not good."

Different NLP techniques represent or process this sentence differently.

### Bag of Words
Counts individual words:
- product: 1
- not: 1
- good: 1

It ignores their order.

### TF-IDF
Assigns weights to words according to their frequency in the document and across the document collection.

The word "not" may receive a high weight if it is uncommon, but TF-IDF does not automatically understand its effect on sentiment.

### N-grams
Captures local word sequences:
- the product
- product is
- is not
- not good

The bigram "not good" may provide a useful feature for negative sentiment.

### Text Classification
A trained sentiment model predicts:
NEGATIVE

### Named Entity Recognition
May identify entities if any are present.

This example contains no obvious named person, organization, or location.

### Semantic Similarity
Can compare the review with another sentence, such as:
"The product is terrible."

A suitable semantic representation may identify that both sentences express similar negative opinions.

### Traditional NLP Limitation
A simple word-count model may not adequately represent the role of "not", while a model using bigrams may handle this particular example better.

## 9. Final Summary

Classical NLP techniques convert text into numerical features and use those features to analyze language.

1. **Bag of Words:** Represents text using word occurrence counts.
2. **TF-IDF:** Weights terms according to their importance within a document collection.
3. **N-grams:** Represents consecutive sequences of words or characters.
4. **Text Classification:** Assigns predefined labels to text.
5. **Named Entity Recognition:** Identifies and categorizes named entities.
6. **Semantic Similarity:** Measures how similar two texts are in meaning or representation.
7. **Traditional NLP Limitations:** Includes weak contextual understanding, loss of word order in BoW, sparse features, and difficulty handling ambiguity.

Key takeaway:

Traditional NLP techniques are important foundations for understanding how text is represented and analyzed. They remain useful for many practical tasks and provide a basis for understanding more advanced approaches, including word embeddings, recurrent neural networks, Transformers, and large language models.
